# カーパックの作り方

[English](README.md) | **日本語**

KurumaMod に車を足すのに **Java は要らない**。JSON とモデルだけの MOD jar を 1 つ作って `mods/` に入れれば車種が増える。

この `carpack/example/` フォルダは**そのまま動く見本**で、車を 1 台と部品を 1 つ足す。

| id | 何の見本か |
|---|---|
| `kurumamod_example_carpack:sample` | 車体メッシュ・テクスチャ・灯火まで自前で持つ、一通り揃った例 |
| `kurumamod_example_carpack:deep_dish` | ホイールの部品。換装画面のスライダーへ既定値を渡せることの例 |

（隣の `carpack/basic/` はプレイヤーへ配っている公式パック。作りは同じで、
説明の類を取り払ったもの。**出来上がったパックに何が入るか**はそちらを見るとよい。）

**この見本は自由に使ってよい。**
コピーして自分のカーパックの土台にしてよく、表示も許諾も要らない。

---

## 1. まず動かしてみる

このフォルダの中身を zip で固めて `.jar` に改名し、`mods/` に入れるだけ。

```bash
cd carpack/example
jar --create --file ../kurumamod_example_carpack.jar .     # JDK があれば
zip -r ../kurumamod_example_carpack.jar .                  # 無ければ zip でも同じ
```

```powershell
# Windows（JDK が無いとき）
Compress-Archive -Path * -DestinationPath ..\kurumamod_example_carpack.zip
Rename-Item ..\kurumamod_example_carpack.zip kurumamod_example_carpack.jar
```

**`META-INF/` と `pack.mcmeta` が jar の直下に来ること。** フォルダごと固めると一段深くなり、
`mods/` に入れても何も起きない。上のコマンドが `example` の**中**で実行されているのはこのため。

起動してクリエイティブタブを見ると、サンプルカーが増えている。

## 2. 自分のパックを作る

サンプルをコピーして、 `kurumamod_example_carpack` を自分の名前に、`sample` を自分の車種名に置き換える。
これが作業のほぼすべて。

```
carpack/example/
├─ META-INF/mods.toml                              ← modId をここで決める
├─ pack.mcmeta
├─ kurumamod_example_carpack.png                   ← MOD 一覧に出る画像（mods.toml の logoFile）
├─ data/kurumamod_example_carpack/cars/sample.json ← 諸元（走り）
└─ assets/kurumamod_example_carpack/
   ├─ vehicles/sample.json                         ← 見た目
   ├─ lang/{ja_jp,en_us}.json                      ← 表示名
   ├─ models/entity/sample.obj + .mtl              ← 車体メッシュ
   └─ textures/entity/sample.png
```

（`README.md` と `CURSEFORGE.md` はこの見本の説明書きなので、消しても入れたままでもよい。`CURSEFORGE.md` は配布ページの説明文のひな形として使える。）

**車種 id を決めると、他の名前は全部そこから決まる。** `mypack:ae86` にするなら:

| | 名前 |
|---|---|
| 諸元 | `data/mypack/cars/ae86.json` |
| 見た目 | `assets/mypack/vehicles/ae86.json` |
| 表示名の翻訳キー | `car.mypack.ae86`（lang に書く） |

名前がずれても、エラーは出ない。黙って既定値に落ちる。  
諸元だけあって見た目の名前が違えば、走るのに姿だけ既定の車になる。ここを揃えるのがいちばん大事。

決まりごと:

- **大文字と空白は使えない。** 名前空間は `a-z 0-9 _ . -`、車種名はこれに `/` を加えたもの
- **名前空間（`mypack`）は `mods.toml` の `modId` と同じにする。** 違えても動くが、他のパックと衝突したときにどちらが読まれるか分からなくなる
- **ただし `modId` は名前空間より狭く、`-` も `.` も使えない**（`^[a-z][a-z0-9_]{1,63}$`）。外れると読み込みが `Invalid modId` で落ちるので、**揃えるなら区切りは `_` だけで書く**（この見本の `kurumamod_example_carpack` がそれ）
- **サブフォルダは使わない。** `cars/toyota/ae86.json` は id が `mypack:toyota/ae86` になり、 翻訳キーが `car.mypack.toyota/ae86` という不格好なものになる
- lang を書かなければ、表示名は `ae86` とそのまま出る

## 3. 諸元を定義する（`data/<pack>/cars/<car>.json`）

**手で数字を書くより、ゲーム内で作って書き出したものを持ってくるのがよい。**

1. ゲーム内で車に乗り、**G** で調整画面を開いて詰める
2. 「プリセット」から名前を付けて保存する
3. `config/kurumamod-setups.json` から該当の 1 件をコピーして、`cars/<car>.json` の `values` に貼る

**書かなかった項目は既定値になる。** 既定の車から変えたいところだけ書けばよく、本体の項目が増えても古いカーパックはそのまま読める。

`_` で始まるキーは読み飛ばされるので、`"_comment": "..."` で理由を残せる （JSON にコメントは書けないため）。

書ける項目の全リストは[付録 B](#b-諸元--datapackcarscarjson)にある。

### 単位は内部単位。**角度はラジアン**

調整画面が度で見せている項目でも、ファイルにはラジアンで書く。`max_steer` を 「32 度のつもりで `32.0`」と書くと **32 ラジアン**が通り、エラーも警告も出ない（既定は 35 度 ＝ `0.6109`）。  
**桁を見て気づけないので、ゲーム内で書き出すのが間違い無い。**

| 種類 | 単位 |
|---|---|
| 長さ | m（cm ではない） |
| 質量 | kg |
| 角度 | **rad**（度ではない） |
| バネ定数 | N/m |
| トルク | N·m |
| 回転数 | rpm |


## 4. 見た目を定義する（`assets/<pack>/vehicles/<car>.json`）

**ここに諸元を書いてはいけない。** 挙動を決める値は `data/` 側だけが持つ。

書かなかった項目は既定値になるので、全部書く必要はない。全リストは[付録 A](#a-見た目--assetspackvehiclescarjson)にある。

要点だけ:

- **モデルとテクスチャは名前空間付きで指す**ので、自前で用意せず KurumaMod のものを借りてもよい（サンプルカーもタイヤは借りている）
- `designWheelBase` / `designWheelRadius` は「**メッシュが何 m で作られているか**」であって、この車の寸法ではない。実際の寸法は諸元側にあり、その比で自動的に拡大される
- 座席の位置もここで決める（運転席は右）

## 5. メッシュを作る（Blender）

**Blender の作業そのものは別のマニュアルにまとめてある** — [車両モデル作成マニュアル](https://static.jdm-mc.com/manual/MODELING.html)。
同じものが**このフォルダの `MODELING.html`** に入っている。ブラウザで開けばオフラインでも読める。
原点の合わせかた、名前で決まる部位（灯火・ガラス・ミラー）、書き出し設定の落とし穴、症状別の直しかたまで、
画面の絵つきで通しで書いてある。**Blender を触ったことがないなら、まずそちらを読むこと。**

ここに残してあるのは要点だけ:

- 単位は**メートル**。全長・全幅・全高に決まりは無い
- **車体の原点は、地面の高さ・前後輪の中点・左右中央**
- **タイヤは左側用を 1 つだけ**作る（右側は鏡像で描かれる）
- 三角形化して書き出す。エクスポート設定は Blender の既定のままでよい

寸法合わせのゲージが `tools/blender_gauge.py` にある。これに合わせて作ればJSON で拡大率をいじる必要がない（`sample.obj` がそうしている）。  
Blenderでのケージの適用方法は、スクリプト作成 → 新規 → (貼り付け) → 実行。エクスポート時は除外してよい。

### ライトはオブジェクト名で決まる

`car.obj` の中のオブジェクト名（Blender のオブジェクト名がそのまま効く）:

| 名前 | 扱い |
|---|---|
| `light_head` | ヘッドライト。点灯時に明るさ最大で描かれ、光の筋の起点になる |
| `light_tail` | テールランプ。常時うっすら、ブレーキで最大 |
| `light_reverse` | バックランプ。段が R のとき |
| それ以外 | 車体 |

**`light_` で始まる名前を勝手に増やしてはいけない。** 車体の描画からは `light_` 全部が除外されるのに、実際に描かれるのは上の 3 つだけなので、**`light_fog` のような名前を付けるとそこが穴になって何も描かれない。**

**役割ごとに 1 オブジェクトでよい。左右に分ける必要はない**——ミラーモディファイアがそのまま使える。光の筋の位置も向きもメッシュから読むので、JSON に座標は要らない。

**レンズの色は、UV 展開したかどうかで決まる側が変わる。**

| レンズの UV | 色を決めるのは |
|---|---|
| 1 点に潰れている | **KurumaMod**（ヘッドは電球色、テールは赤、バックは白）。テクスチャの白い画素を 1 つ指すだけでよい |
| 展開されている | **テクスチャ**。Blender で塗った色がそのまま出る |

二重に色が掛かることはない（展開されているレンズには白が掛かる）。**点灯・消灯の明暗は
どちらの場合も KurumaMod が持つ**ので、テクスチャで暗くしておく必要はない。

## 6. うまくいかないとき

**カーパックは失敗しても黙っている**（壊れた JSON も、ずれた名前も、その 1 件を捨てて先へ進む）。症状から当たりを付ける:

| 症状 | 見るところ |
|---|---|
| MOD 一覧にすら出ない | `META-INF/mods.toml` が jar の直下にあるか（フォルダごと固めていないか） |
| 車種が 1 台も増えない | `data/<pack>/cars/*.json` があるか。ログの `車種を N 件読み込みました` を見る |
| その 1 台だけ増えない | その JSON が壊れている。理由がログに残っている |
| 走るが、姿が既定の車 | `assets/<pack>/vehicles/` のファイル名が諸元と一致しているか |
| 表示名が `ae86` のまま出る | lang の翻訳キーが `car.<pack>.<car>` になっているか |
| 車体とタイヤの位置が合わない | `designWheelBase` / `designWheelRadius` がメッシュの実寸か |
| 舵が異常に切れる／効かない | 角度を度で書いていないか（**ラジアン**） |

詰めている最中は、**諸元は `/reload`、見た目は F3+T** で入れ直せる（ゲームを再起動しなくてよい）。

**カーパックを外しても壊れない。** 知らない車種は既定の車として走り、id は覚えているので入れ直せば元に戻る。

## 付録: JSON で書ける項目の全リスト

**書かなかった項目は既定値**になるので、全部書く必要はない。ここは「何が書けるか」を引くための一覧で、詰め方は上の 3 章・4 章にある。

### A. 見た目 — `assets/<pack>/vehicles/<car>.json`

これで全部（14 項目）。ここに無いキーは書いても読まれない。

| キー | 型 | 既定値 | 意味 |
|---|---|---|---|
| `body.model` | id | `kurumamod:models/entity/car.obj` | 車体の OBJ |
| `body.texture` | id | `kurumamod:textures/entity/car.png` | 車体のテクスチャ |
| `body.offset` | `[x,y,z]` | `[0,0,0]` | 車体の平行移動 [m]（+X 右・+Y 上・-Z 前） |
| `body.scale` | 数字 1 つ or `[x,y,z]` | `1.0` | 車体の拡大率。原点が地面なので**上へ伸びる** |
| `wheel.model` | id | `kurumamod:models/entity/wheel.obj` | タイヤの OBJ |
| `wheel.texture` | id | `kurumamod:textures/entity/wheel.png` | タイヤのテクスチャ |
| `wheel.offset` | `[x,y,z]` | `[0,0,0]` | タイヤの平行移動 [m]。**X は「外向き」**（左右で符号が反転する） |
| `wheel.scale` | 数字 1 つ or `[x,y,z]` | `1.0` | **X は太さ、Y・Z は直径**。Y・Z を触ると接地が崩れる（直径は諸元の `wheel_radius` で変える） |
| `wheel.camber` | 数字 | `0.0` | キャンバー角 [**度**]。負で「上が内側」。**見た目だけで、グリップには効かない** |
| `designWheelBase` | 数字 | `3.12` | **メッシュのホイールアーチが何 m 離れているか。** この車のホイールベースではない |
| `designWheelRadius` | 数字 | `0.45` | **メッシュが何 m の半径で作られているか。** この車のタイヤ半径ではない |
| `designRideHeight` | 数字 | `0.6019` | 車体をシャシー基準面から下げる量 [m] |
| `seat` | `[x,y,z]` | `[0.5, -0.55, 0.2]` | 運転席の位置 [m]。向きは `body.offset` と同じ。助手席は左右反転で自動的に置かれる |
| `shadowRadius` | 数字 | `1.4` | 影の大きさ |

### B. 諸元 — `data/<pack>/cars/<car>.json`

```json
{
  "order": 10,
  "values": {
    "mass": 1500.0,
    "peak_torque": 200.0
  }
}
```

- `order` … 一覧での並び順（既定 `100`）
- `values` … 諸元。**省略して根に直接書いてもよい**
- **`_` で始まるキーは読み飛ばされる**ので、`"_comment": "..."` で理由を残せる
- **単位は内部単位。角度はラジアン**（[単位は内部単位](#単位は内部単位角度はラジアン)）
- **範囲は調整画面のスライダーの範囲であって、検証ではない。** 外れた値もそのまま通るので、極端な数字を書けば破綻した車も作れる

#### 足まわり

| 名前 | 調整画面での名前 | 単位 | 既定 | 範囲 |
|---|---|---|---|---|
| `stroke` | ストローク | m | 0.25 | 0.15 – 0.80 |
| `front_anti_roll` | フロント スタビライザー | N/m | 2500 | 0 – 20000 |
| `rear_anti_roll` | リア スタビライザー | N/m | 1500 | 0 – 20000 |

**足を硬くしたいときは `stroke` を短くする。** 沈み込みがストロークの 39.2% で固定なので、短いほどバネもダンパーも硬くなる。

#### タイヤ

| 名前 | 調整画面での名前 | 単位 | 既定 | 範囲 |
|---|---|---|---|---|
| `friction` | グリップ | — | 1.0 | 0.3 – 1.5 |
| `cornering_stiffness` | コーナリングパワー | — | 12.0 | 4 – 25 |
| `rear_cornering_bias` | 後輪の踏ん張り（大でアンダー） | — | 1.0 | 0.7 – 1.8 |
| `longitudinal_stiffness` | 縦方向のすべり剛性 | — | 18.0 | 5 – 40 |
| `wheel_radius` | タイヤ半径 | m | 0.45 | 0.25 – 1.10 |

**`friction` に書くのは実際の摩擦係数（μ）。** 調整画面は既定を 1.00 とした相対値で
出している（`CarSpec.REFERENCE_FRICTION` 倍）。いまは基準が 1.0 なので画面の数字が
そのままμだが、基準を変えれば一致しなくなる。

#### 車体

| 名前 | 調整画面での名前 | 単位 | 既定 | 範囲 |
|---|---|---|---|---|
| `mass` | 車重 | kg | 1200 | 500 – 2500 |
| `weight_distribution` | 前後の荷重配分 | 割合（前軸） | 0.56 | 0.35 – 0.70 |
| `wheel_base` | ホイールベース | m | 3.12 | 2.0 – 7.0 |
| `track_width` | トレッド | m | 1.8 | 1.2 – 4.0 |

#### エンジン

| 名前 | 調整画面での名前 | 単位 | 既定 | 範囲 |
|---|---|---|---|---|
| `peak_torque` | 最大トルク | N·m | 220 | 60 – 700 |
| `peak_torque_rpm` | 最大トルク回転数 | rpm | 4200 | 1500 – 8000 |
| `torque_falloff` | トルクの落ち方（大で尖る） | — | 0.45 | 0.1 – 0.9 |
| `idle_rpm` | アイドル回転数 | rpm | 800 | 500 – 2000 |
| `redline_rpm` | レブリミット | rpm | 7000 | 4000 – 12000 |
| `engine_brake` | エンジンブレーキ | N·m | 35 | 0 – 120 |
| `engine_inertia` | エンジンの慣性 | kg·m² | 0.25 | 0.05 – 1.0 |

#### 変速機

| 名前 | 調整画面での名前 | 単位 | 既定 | 範囲 |
|---|---|---|---|---|
| `gear_count` | 前進の段数 | 段 | 5 | 3 – 8 |
| `first_gear` | 1 速のギア比 | — | 3.4 | 1.5 – 5.0 |
| `top_gear` | 最高段のギア比 | — | 0.85 | 0.4 – 1.5 |
| `drivetrain_efficiency` | 駆動系の伝達効率 | — | 0.90 | 0.7 – 1.0 |
| `shift_time` | 変速にかかる時間 | 秒 | 0.35 | 0 – 1.5 |
| `manual_transmission` | 変速（0 = AT・1 = MT） | — | 0 | 0 – 1 |

#### 駆動系

| 名前 | 調整画面での名前 | 単位 | 既定 | 範囲 |
|---|---|---|---|---|
| `drive_bias` | 駆動配分（0 = 前・1 = 後） | — | 0.5 | 0 – 1 |
| `diff_preload` | デフ イニシャルトルク | N·m | 0 | 0 – 300 |
| `diff_lock_ratio` | デフ 差動制限率 | — | 0.0 | 0 – 1 |
| `diff_coast_ratio` | デフ 戻し側の効き | — | 0.5 | 0 – 1 |
| `diff_locking_rate` | デフ 回転差への感度 | — | 40 | 0 – 200 |

`diff_lock_ratio` と `diff_preload` がどちらも 0 ならオープンデフ。`diff_coast_ratio` は 0 で 1way、0.5 で 1.5way、1 で 2way。

#### ブレーキ・抵抗

| 名前 | 調整画面での名前 | 単位 | 既定 | 範囲 |
|---|---|---|---|---|
| `abs` | ABS（0 で無効） | 強さ | 0.7 | 0 – 1 |
| `max_speed` | 最高速度 | **m/s** | 69.4（＝250km/h） | 5.56 – 97.2 |
| `rolling_resistance` | 転がり抵抗 | — | 0.15 | 0 – 1 |
| `drag` | 空気抵抗係数 | — | 0.0004 | 0.0001 – 0.005 |

`max_speed` は暴走を止めるための上限で、**実際の最高速はトルクと抵抗から決まる**。抵抗と釣り合う速度より必ず上に置くこと（下げると、そこに張り付いてトルクを変えても最高速が動かない車になる）。

#### 操作

| 名前 | 調整画面での名前 | 単位 | 既定 | 範囲 |
|---|---|---|---|---|
| `max_steer` | 最大切れ角 | **rad** | 0.6109（＝35 度） | 0.1745 – 0.8727 |
| `steer_grip_margin` | 切れ角の余裕（大で滑らせやすい） | — | 1.1 | 0.8 – 8.0 |
| `visual_slip_limit` | 見た目のタイヤ角（0 で無効） | **rad** | 0.7854（＝45 度） | 0 – 1.5708 |
| `steer_rate` | 舵が入るまでの時間 | 秒 | 0.30 | 0 – 1 |
| `steer_return` | 舵が中立へ戻る時間 | 秒 | 0.18 | 0 – 1 |
| `self_aligning` | 舵の自己復元（0 で中立へ戻る） | — | 0.0 | 0 – 1 |
| `pedal_press` | ペダルを踏みきる時間 | 秒 | 0.25 | 0 – 1 |
| `pedal_release` | ペダルを戻しきる時間 | 秒 | 0.12 | 0 – 1 |
| `traction_control` | トラクションコントロール（0 で無効） | 強さ | 1.0 | 0 – 1 |

### C. 書いても読まれないもの

**他の諸元から決まる値は、書いても黙って捨てられる。** 本体が計算する:

| 決まるもの | 何から |
|---|---|
| バネ・ダンパー・バンプストップ | `mass` / `weight_distribution` / `stroke` |
| 重心高 | 停車時の車高 |
| 慣性モーメント 3 つ | `mass` と `wheel_base` / `track_width` |
| 車輪の慣性・登坂できる段差・終減速比 | `wheel_radius` |
| 制動配分 | `weight_distribution` と重心高とホイールベース |
| ブレーキとサイドブレーキの効き | `friction` |
| 変速点・バックの最高速 | `redline_rpm` とギア比 |

そのため「タイヤ半径を変えたらファイナルも直す」「寸法を変えたら慣性も」といった**組み合わせの手直しは要らない**。半径を変えればギアリングも車高も登坂力も一緒に動く。
