Only when you need it

置き換える場所を 1 つずつ確かめたい

kurumamod_example_carpack を、自分のパックの名前（例 mypack）に全部置き換えます。

  1. META-INF/mods.toml と META-INF/neoforge.mods.toml の modId を変える。displayName・description・version も自分のものにする
  2. assets/kurumamod_example_carpack/ と data/kurumamod_example_carpack/ のフォルダ名を modId と同じにする
  3. JSON の中の kurumamod_example_carpack:（モデルのパス）と、lang のキー（car.kurumamod_example_carpack.sample など）も置き換える
  4. MOD 一覧の画像を変えるなら、png を差し替えて logoFile の名前を合わせる
  • modId に使えるのは a-z 0-9 _ だけ（先頭は英字）。- や . を入れると、ゲームが起動時に Invalid modId で落ちる
  • フォルダ名（名前空間）は modId と同じにする。違っても動くが、ほかのパックとぶつかったときにどちらが読まれるか分からない
  • 車種のファイル名と名前の決まりは車の 6 章
Check each place to replace, one by one

Replace every kurumamod_example_carpack with your pack's name (e.g. mypack).

  1. Change modId in META-INF/mods.toml and META-INF/neoforge.mods.toml. Make displayName, description and version your own too
  2. Rename the folders assets/kurumamod_example_carpack/ and data/kurumamod_example_carpack/ to match modId
  3. Replace kurumamod_example_carpack: inside the JSON (model paths) and in the lang keys (car.kurumamod_example_carpack.sample and so on)
  4. For your own mod-list image, swap the png and update logoFile to its name
  • modId may only use a-z 0-9 _ (starting with a letter). A - or . crashes the game at start-up with Invalid modId
  • Make the folder name (the namespace) the same as modId. It works otherwise, but if two packs collide you cannot tell which one wins
  • Car file names and naming rules are in chapter 6 of the Car guide

When it doesn't work
  • Not in the mod list — you zipped the folder itself (META-INF/ is not at the top of the jar), or modId contains - or .
  • No car in the tab — data/mypack/cars/ae86.json is in the wrong place or not valid JSON. The reason is in the log
  • It appears, but with the default car's body — the look JSON's file name differs from the spec's, or the body.model path or namespace (mypack:) is wrong
  • The display name shows as ae86 — the lang key is not car.mypack.ae86
  • The body is too big, too small, or off from the wheels — it does not match the gauge. Write your real sizes into designWheelBase and designWheelRadius (chapter 6)

Other symptoms are in chapter 3 of Shipping.

ゲージに合わせずに作りたい（作ってしまった）

それでも動きます。実際に作った寸法を、見た目の JSON の designWheelBase（ホイールアーチの前後の距離）と designWheelRadius（タイヤの半径）に書きます（6 章）。ゲームがその比で車体を拡大・縮小して、ゲージの大きさに合わせます。

Build without matching the gauge (or you already did)

It still works. Write the sizes you actually built into designWheelBase (distance between the arches) and designWheelRadius (wheel radius) in the look JSON (chapter 6). The game scales the body by that ratio to fit the gauge size.

実車と同じ大きさのゲージにしたい

スクリプトの先頭の SCALE = 1.2 を 1.0 にします。そのときは諸元（data/<pack>/cars/<car>.json）の wheel_base・track_width・wheel_radius も同じ寸法に揃えます（8 章）。揃えないと、タイヤだけが元の位置と大きさで出ます。

Leave it alone for your first car.

2Build the body

車体のメッシュを作る章です。決まりは原点の位置と向きだけで、大きさと形は自由です。

This chapter is about modelling the body. The only rules are where the origin is and which way the car faces; size and shape are up to you.

最小の車体を作る

Make a minimal body

  1. Blender前を −Y、上を +Z に向けて作る。Blender の標準の向きのまま（テンキー 1 で正面から見た向き）
  2. Blenderワールド原点が「地面の高さ・前後輪のちょうど中間・左右の中央」に来るように置く。ゲージのとおりに作れば、そうなっている
  3. Blenderタイヤハウスを、ゲージのタイヤに合わせて切る。

これで、書き出せばゲームのタイヤと車体が合います。

  1. BlenderFace the car towards −Y with +Z up. That is Blender's default (numpad 1 looks at the front)
  2. BlenderPut the world origin at ground level, exactly halfway between the axles, on the centreline. If you follow the gauge, it already is
  3. BlenderCut the wheel arches around the gauge wheels.

Once exported, the body and the in-game wheels line up.

Model half and mirror it

Use a mirror modifier. The exporter applies it for you, so you don't need to press "Apply".

The one exception is the glass of the two door mirrors, which must be separate objects (mirrors in chapter 3).

ボンネットやバンパーを別のオブジェクトに分けたい

分けても分けなくても同じです。ゲームは名前の決まっていないオブジェクトを全部まとめて車体として描きます。同梱の車体は作業のしやすさで body / hood / trunk / bumper_f / bumper_r に分けてあります。

ライト・ガラス・ミラー・付け替える部品だけは名前で働きが決まるので、別のオブジェクト（または別のマテリアル）にします（3 章）。

Split the bonnet or bumpers into their own objects

Split or not, it makes no difference. The game draws every object without a special name as body. The bundled body is split into body / hood / trunk / bumper_f / bumper_r only for convenience while modelling.

Lights, glass, mirrors and swappable parts are the exception: their names decide what they do, so they need their own objects (or materials) (chapter 3).

車内（内装）も作りたい

作らなくてもかまいません。何も作らなければ、車体の裏面がそのまま内装として見えます。作るなら、ふつうの車体として作れば描かれます。座席の位置は見た目の JSON の seat で決まり、座席のメッシュとは関係ありません（6 章）。

Model an interior

You don't have to. Without one, the back faces of the body show through and serve as the cabin. If you do model one, build it as ordinary body and it is drawn. Where the player sits comes from seat in the look JSON, not from any seat mesh (chapter 6).

ポリゴン数の目安を知りたい

あまり気にしなくてかまいません。同梱の車体は 671 面、タイヤは 344 面です。面は四角形のままにしておくと軽く描けます（5 章）。

How many polygons?

Don't worry much about it. The bundled body is 671 faces and the wheel 344. Keeping faces as quads draws faster (chapter 5).

うまくいかないとき
  • 走るとタイヤがボディを突き抜ける … タイヤハウスがゲージのタイヤに合っていない
  • 車体が地面に埋まる・浮く … 原点を車体の底に置いている。地面の高さ（Z = 0）へ動かす
  • タイヤが前後にずれる … 原点が前後輪の中間にない。全長の中心に置いていないか見る
  • 前後が逆・左右が鏡像 … 書き出しの Forward Axis を触った（5 章）
When it doesn't work
  • Tyres poke through the body when driving — the arches don't match the gauge wheels
  • The body sinks into the ground or floats — the origin is at the underside of the body. Move it to ground level (Z = 0)
  • The wheels sit too far forward or back — the origin is not halfway between the axles. Check you didn't use the middle of the overall length
  • Front and back swapped, or mirrored — Forward Axis was changed on export (chapter 5)

3ライト・ガラス・ミラー（名前で決まる機能）

3Lights, glass and mirrors (names that do things)

オブジェクトに決まった名前を付けるだけで、ライトが光り、窓が透け、ミラーに後ろが映ります。JSON には何も書きません。

Give an object one of a few set names and it lights up, turns see-through or reflects what is behind. Nothing goes into the JSON.

ライトを光らせる

Make the lights work

  1. Blenderライトのレンズを別のオブジェクトにして、名前を付ける。ヘッドライトは light_head、テールランプは light_tail、バックランプは light_reverse。左右で 1 つのオブジェクトでよい（ミラーモディファイアのままでよい）
  2. Blenderレンズの面を、車体から 1〜2mm 浮かせる。
  3. Blenderレンズの UV は展開せず、1 点に潰してテクスチャの白い画素に置く。色はゲームが付ける

これで、L でヘッドライトが点き、テールランプはいつもうっすら光ってブレーキで明るくなり、ギアを R に入れるとバックランプが点きます。

  1. BlenderMake each lens its own object and name it. light_head for headlights, light_tail for tail lights, light_reverse for reverse lights. One object for both sides is fine (a mirror modifier is fine)
  2. BlenderFloat the lens faces 1–2 mm proud of the body.
  3. BlenderDon't unwrap the lens: collapse its UVs to one point on a white pixel of the texture. The game adds the colour

L now turns the headlights on, the tail lights glow dimly and brighten under braking, and the reverse lights come on in R.

light_fog のような名前を付けると、そこが穴になって何も描かれません。フォグランプは light_head に含めるか、ふつうの車体として作ります。

ONLY THESE THREE light_ NAMES

Name something light_fog and it becomes a hole where nothing is drawn. Fold fog lights into light_head, or model them as plain body.

窓を透けさせる

Make the windows see-through

これで、窓が透けます（濃さは 0.35）。

  1. BlenderMake the windows their own object and start the name with glass. glass, glass_side, glass.front and so on

The windows are now see-through (opacity 0.35).

ミラーに後ろを映す

Make the mirrors reflect

  1. Blender鏡を別のオブジェクトにして、名前を付ける。ルームミラーは mirror_rear、ドアミラーは mirror_left と mirror_right。筐体ごとの箱 1 つでよい
  2. Blender左右のドアミラーは、別々のオブジェクトにする。ミラーモディファイアで 1 つにしたままにしない（適用してから分ける）
  3. Blender鏡になる面（いちばん広い平らな面）を、運転席のほうへ向ける。角度は合わせなくてよい
  4. ゲームH のメニューで、ミラーを入れる。既定は切

これで、ミラーに後ろの景色が実際に映ります。

  1. BlenderMake each mirror its own object and name it. mirror_rear for the rear-view mirror, mirror_left and mirror_right for the door mirrors. One box for the whole housing is fine
  2. BlenderKeep the two door mirrors as separate objects. Don't leave them joined by a mirror modifier (apply it, then separate)
  3. BlenderTurn the mirror face (the largest flat face) towards the driver. You don't need to aim it
  4. GameTurn mirrors on in the H menu. They are off by default

The mirrors now show what is really behind you.

Change how dark the glass is

Give the window a material and turn its Alpha down (0.2 for lighter, 0.6 for darker). That value is the opacity. With Alpha left at 1, or no material at all, it is 0.35.

Keep the exported .mtl next to the OBJ; it carries the opacity.

Split the windows into several objects

Any number is fine as long as each starts with glass (glass.front, glass.front_side, glass.rear and so on). Put _ or . right after glass; a name that runs straight on, like glasshouse, is not glass.

Unlike light_, new glass names never leave a hole.

Separate the mirror housing from the glass

Give the housing an ordinary name (body_mirror_left in the sample) and name only the glass plate mirror_left. Then there is no doubt about which face reflects.

If the whole housing is one mirror_ object, only its largest flat face reflects; the other faces are drawn as ordinary body.

Put a light on a part such as a wing

Assign a light material to faces inside the part object (part_…). For a high-mounted brake light on a GT wing, use light_tail. Take the wing off and the lamp goes with it.

Mirrors inside a part don't reflect (they are drawn as plain faces). How to make parts is in chapter 2 of the Parts guide.

仕組みを知りたい（ミラーに何が映るか）
  • 何を映すかは、車に対して決まっています。板の角度は使いません。実車で乗った人がミラーを合わせるのと同じで、作った角度は「合わせる前の姿」です
  • ルームミラーは真後ろを、1 度だけ下向きに映します
  • ドアミラーは 1.5 度下向きで、地平線が鏡の中ほどより少し上に来ます。外へは、鏡の内側 15% に自分の車の横腹が映るところまで振ります
  • 横に映る幅は決まっています（ルームミラー 34 度、ドアミラー 22 度）。縦は鏡の縦横比で決まり、横長に作るほど縦に狭くなります
  • ルームミラーかドアミラーかは、名前ではなく鏡の位置で決まります。車の中心から左右 0.35m 以内ならルームミラーです。left / right の名前が実際の左右と逆でも正しく映ります
  • UV は要りません。面の中の位置がそのまま使われます
  • 鏡ごとに、その位置から世界をもう一度描いています。左右のドアミラーを 1 つのオブジェクトにすると、左右で同じ景色が映るのはこのためです
How it works (what a mirror shows)
  • What each mirror looks at is fixed relative to the car. The angle of the plate is not used. Like a real driver adjusting the glass after getting in, the angle you modelled is only the "before adjustment" pose
  • The rear-view mirror looks straight back, 1° down
  • Door mirrors look 1.5° down, putting the horizon a little above the middle of the glass. They are turned outward until your own car's flank fills the inner 15% of the glass
  • The horizontal field of view is fixed (34° rear-view, 22° door). The vertical follows the glass's aspect ratio: the wider you make it, the narrower the vertical view
  • Whether it is a rear-view or a door mirror is decided by where it is, not its name: within 0.35 m of the car's centreline it is the rear-view mirror. If left / right are swapped, it still reflects correctly
  • No UVs needed. The position within the face is used directly
  • Each mirror redraws the world from its own position. That is why two door mirrors joined into one object show the same view
うまくいかないとき
  • ライトを足したところが穴になる … light_head / light_tail / light_reverse 以外の light_ 名を付けた
  • レンズがチラつく … レンズの面が車体と同じ面にある。1〜2mm 浮かせる
  • レンズの色がおかしい … 展開した UV が、テクスチャの塗っていない場所を指している。1 点に潰して白い画素に置くか、テクスチャに色を塗る
  • 窓が透けない … 名前が glass で始まっていない（glasshouse のように続けていないか）。マテリアルの Alpha を使っているなら .mtl を一緒に置いたか
  • ミラーが映らない … H で入れたか。描画設定が「最高（Fabulous）」のときと、シェーダーパックを使っているときは映らない（暗いガラスになる）
  • 左右のミラーに同じ景色が映る … ミラーモディファイアで 1 つのオブジェクトのまま。適用してから分ける
  • ドアミラーが真後ろしか映さない … 鏡が車の中心から 0.35m 以内にあり、ルームミラーとして扱われている
  • ログに役目が食い違うと出る … オブジェクト名とマテリアル名が違う働きを指している。マテリアルのほうが使われている
When it doesn't work
  • A hole where you added a light — you used a light_ name other than light_head / light_tail / light_reverse
  • The lens flickers — the lens sits flush with the body. Float it 1–2 mm
  • The lens is the wrong colour — its unwrapped UVs point at an unpainted part of the texture. Collapse them onto a white pixel, or paint the texture
  • Windows aren't see-through — the name doesn't start with glass (or runs straight on, like glasshouse). If you use material Alpha, is the .mtl next to the OBJ?
  • Mirrors show nothing — did you turn them on in H? They don't reflect with graphics set to "Fabulous" or with a shader pack (you get dark glass)
  • Both door mirrors show the same view — they are still one object via a mirror modifier. Apply it and separate them
  • A door mirror only looks straight back — it is within 0.35 m of the centreline, so it is treated as the rear-view mirror
  • The log says roles disagree — the object name and the material name ask for different roles. The material's role is used

1Model the wheel

ホイールを Blender で作り、OBJ に書き出すまでです。ホイールは車体とは別のファイルで作ります。

This chapter takes a wheel from Blender to an exported OBJ. Wheels are built in a separate file from the body.

最小のホイールを作る

Make a minimal wheel

  3. Blenderホイールの表（デザイン面）を +X へ向ける。ゲージの矢印の側。作るのは左側用の 1 つだけ
  4. Blenderタイヤも作るなら、ホイールとは別のオブジェクトにして、名前を Tire にする。リムだけで作るなら、この手順は要らない
  5. Blenderゲージを除いてホイールだけを選び、OBJ に書き出す。「Selected Only」を入れ、「Triangulated Mesh」は入れない（設定の全体は車の 5 章と同じ）
  6. ファイル書き出したファイルとテクスチャを置く。assets/mypack/models/entity/my_wheel.obj（.mtl も一緒に）と assets/mypack/textures/entity/my_wheel.png

  1. BlenderIn a new file, place the gauge. Run modeling_tools/blender_wheel_gauge.py from the Scripting tab. It places a 0.45 m radius ring, the axle line, the ground and an arrow marking the outer face
  2. BlenderModel the wheel to fit inside the gauge ring, with the origin at the centre of the axle. If you start from a cylinder, first rotate it with R Y 9 0 so its axis runs left–right (X)
  3. BlenderPoint the face of the wheel (the design side) towards +X, the side the gauge arrow points to. Build the left-hand wheel only
  4. BlenderIf you model a tyre too, make it a separate object from the wheel and name it Tire. Skip this if you only build the rim
  5. BlenderSelect only the wheel (not the gauge) and export it as OBJ. Tick "Selected Only" and leave "Triangulated Mesh" off (the full settings are the same as chapter 5 of the Car guide)
  6. FilePut the exported file and the texture in your pack: assets/mypack/models/entity/my_wheel.obj (with its .mtl) and assets/mypack/textures/entity/my_wheel.png

  "wheel": { "model": "mypack:models/entity/my_wheel.obj",
             "texture": "mypack:textures/entity/my_wheel.png" },
  "designWheelRadius": 0.45
}

このファイルのほかの項目は車の 6 章にあります。

Fit it to my own car

In the car's looks file assets/mypack/vehicles/<car>.json, set the model and texture under wheel, and write the radius you built at as designWheelRadius (outside wheel, at the top level):

{
  "body":  { "model": "mypack:models/entity/my_car.obj",
             "texture": "mypack:textures/entity/my_car.png" },
  "wheel": { "model": "mypack:models/entity/my_wheel.obj",
             "texture": "mypack:textures/entity/my_wheel.png" },
  "designWheelRadius": 0.45
}

The rest of this file is in chapter 6 of the Car guide.

ゲージと違う大きさで作りたい

大きさは自由です。作った半径（m）を、車に履かせるなら designWheelRadius、部品にするなら designRadius（2 章）に書きます。ゲームは、この値と車のタイヤ半径の比で拡大して描きます。

ゲーム内の調整画面でタイヤ半径を変えると、見た目もそのまま追従します。タイヤは接地したまま、車体だけが上がります（リフトアップ）。

Build it at a different size from the gauge

Any size is fine. Write the radius you built at (in m) as designWheelRadius when fitting it to a car, or as designRadius when making it a part (chapter 2). The game scales the mesh by the ratio between this value and the car's tyre radius.

Change the tyre radius in the in-game tuning screen and the model follows: the tyres stay on the ground and the body rises (a lift-up).

タイヤを作らず、KurumaMod のタイヤを使いたい

リムだけで作れば、KurumaMod 標準のタイヤが自動で嵌まります。ホイールごと借りるなら、モデルを kurumamod:models/entity/wheel.obj、テクスチャを kurumamod:textures/entity/wheel.png にします（車の 6 章）。

Skip the tyre and use KurumaMod's

Build only the rim and KurumaMod's own tyre is fitted automatically. To borrow the whole wheel, use kurumamod:models/entity/wheel.obj as the model and kurumamod:textures/entity/wheel.png as the texture (chapter 6 of the Car guide).

仕組みを知りたい（なぜタイヤに Tire と名前を付けるのか）

換装画面でタイヤ（3 章）を選ぶと、ゲームは tire で始まる名前（大文字小文字は問わない）のオブジェクトを隠し、選んだタイヤをリムに嵌めて描きます。

  • タイヤを選んでいない（ノーマル）ときは、あなたのタイヤがそのまま出る
  • 名前が無いと、タイヤもホイールの一部として描かれたままになり、選んだタイヤと重なって見える
  • シェーダーパックの影は、タイヤだけが落とす。地面にスポークの模様が出ない
How it works (why name the tyre Tire)

When a tyre (chapter 3) is picked in the parts screen, the game hides any object whose name starts with tire (in any case) and draws the picked tyre on the rim instead.

  • With no tyre picked (Normal), your own tyre is drawn as it is
  • Without the name, your tyre stays part of the wheel and shows through the picked one
  • With shader packs, only the tyre casts a shadow, so no spoke pattern appears on the ground
うまくいかないとき
  • タイヤが大きすぎる・小さすぎる … designWheelRadius（部品なら designRadius）が、作った半径になっていない
  • 回るとぶれる・地面に埋まる・浮く … 原点が車軸の中心にない。タイヤの底に置いていないか見る
  • タイヤが横倒しで転がる … 回転軸が左右（X）を向いていない。R Y 9 0 で回す
  • 右側のタイヤの表が内側を向く … 表が +X を向いていない。左側用として作り直す（右側は MOD が鏡像にして描く）
  • 1 か所にタイヤが 2 本描かれる … 左右 2 つ作っている。左側用の 1 つだけにする
  • 選んだタイヤと自分のタイヤが重なる … タイヤのオブジェクト名が tire で始まっていない
  • 全体が白い … .mtl を置いていないか、マテリアルが無い。形が正しければ問題ない（色の付け方は車の 4 章）
When it doesn't work
  • Wheels too big or too small — designWheelRadius (or designRadius for a part) is not the radius you built at
  • Wobbles as it spins, sinks into the ground, or floats — the origin is not at the axle centre. Check it is not at the bottom of the tyre
  • Rolls on its side — the spin axis does not run left–right (X). Rotate with R Y 9 0
  • The right-hand wheels face inward — the face is not towards +X. Rebuild it as the left-hand wheel (the mod mirrors it for the right)
  • Two tyres drawn in one place — you modelled both sides. Keep only the left-hand one
  • Your tyre shows through the picked one — the tyre object's name does not start with tire
  • Everything is white — no .mtl, or no material. Harmless if the shape is right (colouring is in chapter 4 of the Car guide)

This chapter is about giving the body colour and detail. The car drives without a texture, so you can build the shape first and paint it later.

Add a minimal texture

  2. BlenderIf you use materials, set Base Color to white (1.0).

必要なときだけ

Only when you need it

UV を張らずに、まず形だけ確かめたい

そのままでかまいません。UV 展開していない面は、テクスチャの 1 点の色で塗りつぶされます。絵がまだ無ければ、白く塗った小さな PNG を置いておけば足ります。

ライトのレンズは、UV を展開しないほうが都合がよいことがあります（3 章）。

Check the shape first, without UVs

That works as it is. Faces without UVs are filled with the colour of a single pixel of the texture. If you have no art yet, a small all-white PNG is enough.

For light lenses, leaving them unwrapped is often the better choice (chapter 3).

タイヤにも自分のテクスチャを使いたい

車体とタイヤは別々のテクスチャを指せます。見た目の JSON の wheel に書きます:

"wheel": { "model": "mypack:models/entity/mywheel.obj",
           "texture": "mypack:textures/entity/mywheel.png" }

タイヤのモデルの作り方はホイールの 1 章にあります。

Use your own texture on the wheels too

Body and wheels can point at different textures. Write it into wheel in the look JSON:

"wheel": { "model": "mypack:models/entity/mywheel.obj",
           "texture": "mypack:textures/entity/mywheel.png" }

How to model the wheel is in chapter 1 of the Wheel guide.

テクスチャを使わず、マテリアルの色だけで塗り分けたい

できます。マテリアルの Base Color が、テクスチャの色に掛け合わされて出ます。テクスチャを白一色にしておけば、マテリアルの色がそのまま出ます。書き出した .mtl を OBJ と一緒に置いてください。色はこのファイルが運びます。

Colour it with material colours only, no texture

You can. A material's Base Color is multiplied over the texture, so with an all-white texture the material colour comes through as is. Keep the exported .mtl next to the OBJ; it carries the colours.

うまくいかないとき
  • テクスチャが暗い … マテリアルの Base Color が Blender の既定の 0.8 グレーのまま。白にする
  • マテリアルの色が出ず、全体が白い … .mtl を OBJ と一緒に置いていない。マテリアルを使わないつもりなら、それで問題ない
  • テクスチャが変わらない … F3+T を押したか。texture のパスと名前空間（mypack:）が合っているか
When it doesn't work
  • The texture comes out dark — the material's Base Color is still Blender's default 0.8 grey. Set it to white
  • Material colours don't show; everything is white — the .mtl is not next to the OBJ. If you don't use materials, that is fine
  • The texture doesn't change — did you press F3+T? Do the texture path and namespace (mypack:) match?

Export the wheel too

The wheel goes into a separate file from the body (for example mywheel.obj), with the same settings. How to build it is in chapter 1 of the Wheel guide. If you borrow KurumaMod's wheel, there is nothing to export.

.mtl は要るのか知りたい

.mtl は、マテリアルの色・ガラスの濃さ・マテリアル名で付けたライトなどの働きを運びます。どれも使っていなければ消してもかまいません。消すと全体が白（テクスチャの色そのまま）になります。

Do I need the .mtl?

The .mtl carries material colours, glass opacity, and roles given by material names (lights and so on). If you use none of those, you may delete it; everything then turns white (the texture as is).

三角形にして書き出したい・凹んだ面がある

三角形にしても描けますが、重くなるだけです。5 角形以上の面は、凹んでいても MOD が正しく割ります。全体を三角形にする必要はありません。

Triangulate on export, or the model has concave faces

Triangulating still works; it just makes the model heavier. The mod splits faces with five or more corners correctly, even concave ones. There is no need to triangulate everything.

仕組みを知りたい（なぜ Forward Axis を触ってはいけないか）

設定には −Z Forward と書いてありますが、Blender の前（−Y）は OBJ では +Z になって出てきます。この読み替えは MOD が済ませているので、既定のままで車は正しく前を向きます。

Forward Axis を変えると、前後と左右がまとめて裏返ります。車体は左右対称なので鏡像になっても気づけず、あとで「タイヤの向きだけおかしい」という形で出てきます。

How it works (why not to touch Forward Axis)

The dialog says −Z Forward, but Blender's front (−Y) actually comes out as +Z in the OBJ. The mod already accounts for that, so the defaults give a car facing the right way.

Changing Forward Axis flips front–back and left–right together. A symmetric body gives no clue it has been mirrored; it shows up later as "only the wheels point the wrong way".

うまくいかないとき
  • 前後が逆・左右が鏡像 … Forward Axis を変えた。既定（−Z / Y）へ戻して書き出し直す
  • ゲージが一緒に書き出された … Selected Only を入れ忘れた。ゲージ（gauge_）は描かれないので害はないが、入れて書き出し直す
  • 片側しかない … ミラーモディファイアが適用されていない。Apply Modifiers を入れたままにする
  • 付け替える部品（part_…）が出ない … 非表示のまま書き出した。非表示のオブジェクトは選べないので OBJ に入らない。全部表示にしてから選ぶ（パーツの 2 章）
  • マテリアルの色やガラスの濃さが出ない … .mtl を OBJ と同じ場所に置いていない
  • 面がねじれる・抜ける … 平面から大きく曲がった面か、辺が交差した面がある。Blender でその面だけ割る
When it doesn't work
  • Front and back swapped, or mirrored — Forward Axis was changed. Put it back to −Z / Y and export again
  • The gauge was exported too — Selected Only was off. Gauge objects (gauge_) are never drawn, so it is harmless, but tick it and export again
  • Only one half of the car — the mirror modifier was not applied. Keep Apply Modifiers on
  • A swappable part (part_…) never appears — it was hidden when you exported. Hidden objects cannot be selected, so they are left out of the OBJ. Unhide everything before selecting (chapter 2 of the Parts guide)
  • Material colours or glass opacity missing — the .mtl is not next to the OBJ
  • Faces twist or disappear — a face is badly non-planar or has crossing edges. Split just that face in Blender

車体の大きさ・位置を合わせたい

ゲージ（1 章）にぴったり合わせて作ったなら、何も書かなくて済みます。合わせられなかったときは、見た目の JSON（assets/mypack/vehicles/ae86.json）のいちばん外側に、メッシュを実際に作った寸法を書きます。

{
  "body":  { "model": "mypack:models/entity/ae86.obj",
             "texture": "mypack:textures/entity/ae86.png" },
  "wheel": { "model": "kurumamod:models/entity/wheel.obj",
             "texture": "kurumamod:textures/entity/wheel.png" },

  "designWheelBase": 3.12,
  "designWheelRadius": 0.45,
  "designRideHeight": 0.6019
}
  • designWheelBase … メッシュの前後のホイールアーチが何 m 離れているか（既定 3.12）。5.2m で作ってしまったなら 5.2 と書けば、既定の車の大きさに縮みます
  • designWheelRadius … メッシュのタイヤが何 m の半径で作られているか（既定 0.45）
  • designRideHeight … 車体をシャシー基準面から下げる量 [m]（既定 0.6019）。車体が埋まる・浮くときに直す
  • どれも「この車の寸法」ではなく「メッシュの寸法」です。実際の寸法は諸元にあり、ゲームはその比でメッシュを拡大します

あとは body の中で細かく直せます:

"body": { "model": "...", "texture": "...",
          "offset": [0.0, 0.02, 0.0],
          "scale": 1.05 }

  • scale … 大きさの微調整。数字 1 つでも [x, y, z] でもよい。原点が地面なので上へ伸びる

Make the body the right size and position

If you built exactly to the gauge (chapter 1), there is nothing to write. If not, write the sizes you actually built the mesh at at the top level of the looks JSON (assets/mypack/vehicles/ae86.json):

{
  "body":  { "model": "mypack:models/entity/ae86.obj",
             "texture": "mypack:textures/entity/ae86.png" },
  "wheel": { "model": "kurumamod:models/entity/wheel.obj",
             "texture": "kurumamod:textures/entity/wheel.png" },

  "designWheelBase": 3.12,
  "designWheelRadius": 0.45,
  "designRideHeight": 0.6019
}
  • designWheelBase — how far apart the front and rear arches are in your mesh, in m (default 3.12). If you built it at 5.2 m, write 5.2 and it shrinks to the default car's size
  • designWheelRadius — the radius your mesh's tyre was built at, in m (default 0.45)
  • designRideHeight — how far to drop the body below the chassis plane, in m (default 0.6019). Change it if the body sinks or floats
  • These describe the mesh, not the car. The car's real sizes are in the spec, and the game scales the mesh by the ratio

Then fine-tune inside body:

"body": { "model": "...", "texture": "...",
          "offset": [0.0, 0.02, 0.0],
          "scale": 1.05 }
  • offset — shift the body, in m. [x, y, z] with +X right, +Y up, −Z forward
  • scale — fine size adjustment; one number or [x, y, z]. The origin is on the ground, so it grows upward

For a bigger car, change the spec instead. Widen the wheelbase and track in the game's tuning screen, and set body.scale to the same ratio (for 1.2×: 3.12→3.74 m, 1.8→2.16 m, scale 1.2).

座席の位置を直したい

見た目の JSON のいちばん外側に seat を書きます。運転席の位置で、助手席は左右反転で自動的に置かれます。

"seat": [0.5, -0.55, 0.2]
  • [x, y, z] [m]。+X 右・+Y 上・−Z 前。既定は右ハンドル（x が正）
  • 前後（z）は前後輪の中点から、左右（x）と高さ（y）はシャシー基準面の中心から測る
  • 足元の位置で、目線ではありません。一人称の視点はここから 1.62m 上に来ます。目線で決めたいなら 1.62 を引く
  • 座面に合わせると視線が高くなり、目線に合わせると足が床下へ潜ります。どちらにするかは車ごとの好み
  • メッシュから測るときは、designWheelBase などで拡大・縮小された後の大きさで測る
Move the seat

Write seat at the top level of the looks JSON. It is the driver's seat; the passenger seat is mirrored automatically.

"seat": [0.5, -0.55, 0.2]
  • [x, y, z] in m, with +X right, +Y up, −Z forward. The default is right-hand drive (positive x)
  • Front-to-back (z) is measured from the midpoint of the axles; side (x) and height (y) from the centre of the chassis plane
  • It is where the feet go, not the eyes. The first-person camera sits 1.62 m above it; subtract 1.62 to place the eye line instead
  • Match the cushion and the view sits high; match the eye line and the feet sink through the floor. Pick per car
  • If you measure from the mesh, measure it after the scaling from designWheelBase and friends

Change how the wheels look (own wheel, offset, width, camber)

名前の決まりを詳しく知りたい
  • 大文字と空白は使えない。名前空間（mypack）は a-z 0-9 _ . -、車種名はこれに / を加えたもの
  • modId は名前空間より狭く、- も . も使えない（^[a-z][a-z0-9_]{1,63}$）。外れると読み込みが Invalid modId で落ちる。区切りは _ だけにする
  • 名前空間は modId と同じにする。違っても動くが、ほかのパックとぶつかったときにどちらが読まれるか分からなくなる
  • サブフォルダは使わない。cars/toyota/ae86.json は id が mypack:toyota/ae86、翻訳キーが car.mypack.toyota/ae86 になる
  • lang を書かなければ、表示名は ae86 とそのまま出る
  • MOD 一覧に出る画像は mods.toml の logoFile で指す
Naming rules in detail
  • No uppercase, no spaces. Namespaces (mypack) allow a-z 0-9 _ . -; car names allow those plus /
  • modId is stricter: no -, no . (^[a-z][a-z0-9_]{1,63}$). Breaking that fails the load with Invalid modId. Use _ as the only separator
  • Make the namespace the same as modId. It works either way, but if two packs collide you cannot tell which one won
  • No subfolders. cars/toyota/ae86.json becomes the id mypack:toyota/ae86 and the key car.mypack.toyota/ae86
  • Without a lang entry, the display name is simply ae86
  • The image in the mod list is logoFile in mods.toml

仕組みを知りたい（なぜ見た目と走りでフォルダが分かれるのか）

assets/ はプレイヤーのゲームだけが読み、data/ はサーバーが読みます。誰も乗っていない車はサーバーが動かすので、走りを決める値は data/ に置きます。もし assets/ に置けたら、無人の車の動きが各プレイヤーのリソースパック次第になってしまいます。そのため、見た目の JSON に書けるのは見た目だけです。

jar 1 つにすれば、assets/ と data/ の両方が一緒に読まれます。

How it works (why looks and handling live in different folders)

assets/ is read only by each player's game; data/ is read by the server. The server drives cars nobody is in, so handling values belong in data/. If they could live in assets/, a driverless car would behave according to each player's resource pack. That is why the looks JSON can only describe appearance.

In a single jar, both assets/ and data/ are read together.

うまくいかないとき
  • MOD 一覧に出ない … modId に - や . を使っていないか。META-INF/ が jar の直下にあるか（配布の 1 章）
  • 車種が増えない … data/mypack/cars/ae86.json の場所と、JSON の書き間違い。ログに理由が出る
  • 走るのに姿が既定の車のまま … vehicles/ の JSON のファイル名が車種名と同じか。model の名前空間（mypack:）が合っているか
  • 表示名が ae86 のまま … lang のキーが car.mypack.ae86 になっているか
  • 車体だけ大きい・小さい … designWheelBase がメッシュの実寸か
  • 車体が埋まる・浮く … designRideHeight。メッシュの原点が地面の高さにあるか
  • タイヤが大きすぎる・小さすぎる … designWheelRadius がメッシュの実寸か
  • 調整画面で寸法を変えたらタイヤがフェンダーからはみ出した … 仕様。タイヤは諸元に合わせて動き、車体は動かない。車体も合わせるなら body.scale
  • 見た目の JSON に mass などを書いても効かない … 走りの値は data/ の諸元に書く（8 章）

ほかの症状は配布の 3 章にあります。

When it doesn't work
  • Not in the mod list — does modId contain - or .? Is META-INF/ at the top of the jar (chapter 1 of the Shipping guide)?
  • No new car — check where data/mypack/cars/ae86.json is, and the JSON for typos. The reason is in the log
  • It drives but wears the default body — is the vehicles/ JSON named the same as the car? Does the namespace in model (mypack:) match?
  • The display name is just ae86 — is the lang key car.mypack.ae86?
  • Only the body is too big or small — is designWheelBase the real size of your mesh?
  • The body sinks or floats — designRideHeight. Is the mesh origin at ground level?
  • Wheels too big or small — is designWheelRadius the real size of your mesh?
  • After changing sizes in the tuning screen, the wheels stick out of the fenders — expected. Wheels follow the spec; the body does not. Use body.scale to match the body
  • mass and the like in the looks JSON do nothing — handling values go in the spec under data/ (chapter 8)

More symptoms in chapter 3 of the Shipping guide.

  • OGG Vorbis のモノラルにする。Audacity なら「トラック → ミックス → ステレオをモノラルにミックスダウン」してから OGG で書き出す

  • Ogg Vorbis, mono. In Audacity: Tracks → Mix → Mix Stereo Down to Mono, then export as OGG
  • Cross-fade the tail of a loop into its head so there is no seam. About a second is plenty; much shorter and the repetition becomes audible
  • Keep the level steady. The game drives volume from throttle and speed, so any swell inside the file is applied twice and the sound "wobbles"
  • Build the engine a little high. It plays at 0.65× the original pitch at idle and about 3.9× at the redline; a straight recording of a real idle ends up too low

  • subtitle … 字幕の翻訳キー。KurumaMod のもの（subtitles.kurumamod.car_exhaust など）をそのまま借りられる。自分の lang に書いたキーでもよい
  • "name" は sounds/ からのパスで、拡張子を付けない
Change how far a sound carries, or its subtitle
  • attenuation_distance — how far it carries, in blocks (16 if left out). KurumaMod uses 64 for the engine, 48 for squeal, 32 for road noise
  • subtitle — the subtitle's translation key. You can borrow KurumaMod's (subtitles.kurumamod.car_exhaust and so on) or use one from your own lang
  • "name" is the path under sounds/, without the extension

仕組みを知りたい（なぜ高回転用の音源が要るのか）

Minecraft は音程を 0.5〜2.0 倍までしか変えられません。1 つの音源ではレブまで音程が上がりきらないので、1 オクターブ上の音源を exhaust_high として並べ、回転に合わせて 2 つを入れ替えています。

make_octave_up.py は長さを半分にして 1 オクターブ上げます。ループはループのまま出てきます（継ぎ目は増えません）。ステレオを渡してもモノラルにして書きます。

How it works (why a high-rpm sound is needed)

Minecraft can only shift pitch between 0.5× and 2.0×, so one file cannot climb all the way to the redline. The game plays a one-octave-up copy as exhaust_high and cross-fades between the two with rpm.

make_octave_up.py halves the length to go up an octave. A seamless loop comes out seamless, and stereo input is written as mono.

うまくいかないとき

  • 音がうねる … 音源の中で音量が揺れている。一定にする

  • The pitch stops rising near the redline — exhaust_high is missing. Without it the same file plays on the high side, and the pitch caps at 2×

3タイヤを部品にする

ダート用・オフロード用のような、走りが変わるタイヤを作ります。タイヤはホイールとは別の部品で、路面ごとのグリップが変わります。

Make a tyre that changes how the car drives, such as a gravel or mud-terrain tyre. Tyres are a separate part from wheels, and they change grip on each surface.

Make a minimal tyre part

  1. ファイル部品のファイルを置く。data/mypack/car_parts/my_tire.json（ファイル名が部品名）:

    "grip": { "paved": 0.90, "gravel": 1.20 }

Only when you need it

性能の数字を決めたい

書ける項目はこれで全部です。どれもノーマルタイヤに対する倍率で、書かなかったものは 1 です。

{
  "slot": "tire",
  "tire": {
    "stiffness": 0.85,
    "grip":    { "paved": 0.88, "dirt": 1.20, "gravel": 1.25, "sand": 1.10, "snow": 1.10 },
    "rolling": { "paved": 1.15 }
  }
}
  • grip … その路面でのグリップ
  • rolling … その路面での転がり抵抗。大きいほど進みにくい
  • stiffness … 舵を切ってから力が立ち上がるまでの鋭さ。ブロックの大きいタイヤほど小さくする
  • 路面の名前は paved（舗装）・dirt（土・草）・gravel（砂利）・sand（砂）・snow（雪）・ice（氷）
  • 倍率は 0.3〜3.0 に丸めて読む

Choose the numbers

These are all the keys. Every number is a ratio to the Normal tyre, and anything left out is 1.

{
  "slot": "tire",
  "tire": {
    "stiffness": 0.85,
    "grip":    { "paved": 0.88, "dirt": 1.20, "gravel": 1.25, "sand": 1.10, "snow": 1.10 },
    "rolling": { "paved": 1.15 }
  }
}
  • grip — grip on that surface
  • rolling — rolling resistance on that surface. Bigger means harder to keep moving
  • stiffness — how sharply force builds once you steer. Lower it for chunky tread
  • Surface names: paved, dirt (dirt and grass), gravel, sand, snow, ice
  • Ratios are clamped to 0.3–3.0

  1. Blender でタイヤだけのメッシュを作る。原点・回転軸・表の向きはホイールと同じ（1 章）。大きさは自由
  2. OBJ とテクスチャを置く。assets/mypack/models/entity/my_tire.obj と assets/mypack/textures/entity/my_tire.png
  3. 見た目のファイルを置く。assets/mypack/car_parts/my_tire.json（部品と同じファイル名）。必ず "tire" の中に書く:

    "model": "mypack:models/entity/my_tire.obj",

内径と外径はメッシュから測るので、書かなくてかまいません。選んだタイヤは、内径がホイールのリムへ、外径が車のタイヤ半径へ来るように伸び縮みして描かれます。リムの大きいホイールほどサイドウォールが薄くなります。換装画面の「太さ」は、ホイールとタイヤに一緒に効きます。

Change the looks (tread) too
  1. Model the tyre alone in Blender. Origin, spin axis and outer face are the same as a wheel (chapter 1). Any size will do
  2. Put the OBJ and texture in your pack: assets/mypack/models/entity/my_tire.obj and assets/mypack/textures/entity/my_tire.png
  3. Add the looks file assets/mypack/car_parts/my_tire.json (same file name as the part). Always write it inside "tire": 
    {
  "tire": {
    "model": "mypack:models/entity/my_tire.obj",
    "texture": "mypack:textures/entity/my_tire.png"
  }
}

The inner and outer radii are measured from the mesh, so you need not write them. The picked tyre is stretched so its inner edge sits on the wheel's rim and its outer edge at the car's tyre radius; bigger rims get thinner sidewalls. The parts screen's Width slider acts on the wheel and tyre together.

自分のホイールで、タイヤの嵌まる位置を直したい

タイヤの内径（ビード）を置く半径は、次の順に決まります。

  1. ホイールの見た目のファイルに rimRadius（メッシュの寸法・m）が書いてあれば、その値
  2. 無ければ、ホイールに付けたタイヤ（Tire）の内径
  3. それも無ければ、リムのいちばん外側の半径の 95%

位置が合わないときは、ホイールの見た目のファイル assets/mypack/car_parts/my_wheel.json の wheel に rimRadius を書きます:

{
  "wheel": {
    "model": "mypack:models/entity/my_wheel.obj",
    "texture": "mypack:textures/entity/my_wheel.png",
    "designRadius": 0.45,
    "rimRadius": 0.33
  }
}
Fix where tyres sit on my own wheel

The radius where the tyre's inner edge (bead) sits is chosen in this order:

  1. rimRadius in the wheel's looks file, if written (mesh units, m)
  2. otherwise, the inner edge of the tyre you modelled on the wheel (Tire)
  3. otherwise, 95% of the rim's outermost radius

If tyres sit wrong, add rimRadius under wheel in the wheel's looks file assets/mypack/car_parts/my_wheel.json:

{
  "wheel": {
    "model": "mypack:models/entity/my_wheel.obj",
    "texture": "mypack:textures/entity/my_wheel.png",
    "designRadius": 0.45,
    "rimRadius": 0.33
  }
}

  • 見た目が KurumaMod 標準のタイヤのまま … 見た目のファイルで "tire": { ... } の中に書いていない。または assets/ 側のファイル名が data/ 側と違う
  • 選んだタイヤと、ホイールに付いていたタイヤが重なる … ホイールのタイヤのオブジェクト名が tire で始まっていない（1 章）
  • サイドウォールが厚すぎる・薄すぎる … 上の「タイヤの嵌まる位置を直したい」。それでも合わないときは、タイヤの見た目の "tire" に innerRadius / outerRadius（メッシュのタイヤの内径・外径 [m]）を書く
When it doesn't work
  • Listed, but drives like Normal — "tire": { ... } is missing (the log says so)
  • Only some surfaces have no effect — a surface name is misspelt. Unknown names are logged and ignored
  • Still looks like KurumaMod's standard tyre — the looks file is not written inside "tire": { ... }, or the assets/ file name differs from the data/ one
  • The picked tyre and the wheel's own tyre overlap — the wheel's tyre object name does not start with tire (chapter 1)
  • Sidewalls too thick or too thin — see "Fix where tyres sit on my own wheel" above. If that is not enough, write innerRadius / outerRadius (the mesh tyre's inner and outer radius [m]) inside the tyre's "tire"

必要なときだけ

Only when you need it

走りを変えたい（ダウンフォース aero）

効きを調整しない部品（ダックテールなど）は、数字 1 つで書きます。data/mypack/car_parts/ducktail.json:

{
  "slot": "rear_wing",
  "aero": { "rear": 0.25 }
}

換装画面の「角度」で効きを調整できる部品（GT ウイングなど）は、[最小, 最大] で書きます。前にも効かせたいときは front も書きます。data/mypack/car_parts/gt_wing.json:

{
  "slot": "rear_wing",
  "aero": {
    "rear": [0.6, 1.6],
    "front": 0.1,
    "angle": 0.4
  }
}
  • front / rear … 前と後ろを、どれだけ押し付けるか。大きいほど強い（0〜3）。1 で 200km/h のとき約 190kg
  • 目安: ウイング付きの市販車で前後合わせて 0.3〜0.6、GT 系のレーシングカーで 2〜3
  • angle … 「角度」のスライダーの最初の位置（0〜1、省略で 0.5）。角度で変わるのは走りだけで、見た目は動かない
  • 強くするほど高速コーナーは速くなるが、最高速は落ちる。空気抵抗は自動で決まるので、書く項目はない
  • 前を強くすると曲がりやすく（オーバー）、後ろを強くすると安定する（アンダー）

換装画面の右には、その部品のダウンフォースと、付けたときの配分・グリップ・最高速の目安が出ます。

Change how it drives (downforce, aero)

A part whose effect is fixed (a duck tail, say) takes a single number. data/mypack/car_parts/ducktail.json:

{
  "slot": "rear_wing",
  "aero": { "rear": 0.25 }
}

A part whose effect players can adjust with the parts screen's "Angle" slider (a GT wing, say) takes [min, max]. Add front if it should press the front too. data/mypack/car_parts/gt_wing.json:

{
  "slot": "rear_wing",
  "aero": {
    "rear": [0.6, 1.6],
    "front": 0.1,
    "angle": 0.4
  }
}
  • front / rear — how hard it presses the front and rear down. Bigger is stronger (0 to 3). 1 is about 190 kg at 200 km/h
  • Guide: 0.3–0.6 in total for a road car with a wing, 2–3 for a GT race car
  • angle — where the "Angle" slider starts (0–1, default 0.5). The angle changes driving only; the object does not move
  • More downforce makes fast corners quicker but lowers top speed. Drag follows automatically, so there is nothing to write for it
  • More at the front turns in harder (oversteer); more at the rear is more stable (understeer)

The parts screen shows the part's downforce and how balance, grip and estimated top speed change.

オブジェクトに別の名前を付けたい・1 つの部品で複数のオブジェクトを出したい

名前は part_<部品名>（例 part_gt_wing）でも通ります。どちらの決まりにも合わない名前にしたいときは、車の vehicles/<車>.json に対応を書きます。

"parts": {
  "mypack:twin_muffler": { "show": ["part_exhaust-twin", "part_exhaust-twin_tip"] }
}

show に書けるのは part_ で始まる名前だけです。

Free object names, or several objects for one part

part_<part> (e.g. part_gt_wing) works too. For any other name, map it in the car's vehicles/<car>.json:

"parts": {
  "mypack:twin_muffler": { "show": ["part_exhaust-twin", "part_exhaust-twin_tip"] }
}

Only names starting with part_ are allowed in show.

最初から付いている部品にしたい（初期装備）

車の諸元 data/mypack/cars/<車>.json の、values と同じいちばん外側に書きます。

{
  "values": { "mass": 1250 },
  "default_parts": {
    "rear_wing": "mypack:s15_spoiler",
    "exhaust": { "part": "mypack:stock_muffler", "removable": false }
  }
}
  • 換装画面の「純正」が初期装備になる。外せる初期装備のある場所には「なし」も並ぶ
  • "removable": false なら外せない。外すと穴だけ残る部品に使う
  • 置いてある車にも効く。パックで初期装備を変えれば、すでに置いた車も変わる
Have it fitted from the start (default parts)

Put them in the car's spec, data/mypack/cars/<car>.json, at the top level next to values:

{
  "values": { "mass": 1250 },
  "default_parts": {
    "rear_wing": "mypack:s15_spoiler",
    "exhaust": { "part": "mypack:stock_muffler", "removable": false }
  }
}
  • "Stock" in the parts screen becomes the default part. Slots with a removable default also get "None"
  • "removable": false means it cannot come off. Use it for parts that would leave a hole
  • It reaches cars already placed: change the default in the pack and existing cars follow
仕組みを知りたい（なぜ全部を 1 つの OBJ に入れるのか）

ゲームは、車体の OBJ の中に入っている部品のオブジェクトを、表示・非表示で切り替えているだけです。付けている部品のオブジェクトだけを描き、残りは描きません。そのため:

  • OBJ に入っていない部品は出せない。部品だけを別のファイルにして、あとから足すことはできない
  • 非表示のまま書き出したオブジェクトは OBJ に入らないので、出せない
  • 部品を 1 つ増やしたら、車体の OBJ を書き出し直す
  • ほかの人の車には、部品パックだけでは外装パーツを足せない
うまくいかないとき
  • 非表示のまま書き出さない。「選択物のみ」で書き出すと、非表示のオブジェクトは選べないので抜け落ちる
  • 純正の部品も別のオブジェクトにする。body に一体で残した部分は、付け替えても消えない
  • 部品の中の面に light_tail などのマテリアルを割り当てると、部品と一緒に光る（車の 3 章）
  • cars で付けられる車種を絞れる。表示名は part.<パック>.<部品名>
How it works (why everything goes into one OBJ)

The game only shows or hides part objects that are already inside the car's OBJ. It draws the objects of the fitted parts and skips the rest. So:

  • A part that is not in the OBJ cannot appear. You cannot ship a part as a separate file and add it later
  • An object exported while hidden is not in the OBJ, so it cannot appear either
  • Adding a part means exporting the car's OBJ again
  • A parts-only pack cannot add body parts to someone else's car
When it doesn't work
  • Don't export with objects hidden. With "Selected Only", hidden objects cannot be selected and drop out
  • Make stock pieces separate objects too. Anything left merged into body stays, whatever is fitted
  • Faces inside a part with a light_tail material light up with the part (chapter 3 of the Car guide)
  • cars limits which cars can fit it. The display name is part.<pack>.<part>

必要なときだけ

Only when you need it

音を低く・大きくしたい

見た目の JSON を置きます。assets/mypack/car_parts/titanium.json（素性と同じファイル名）:

{
  "exhaust": {
    "pitch": [0.85, 1.00],
    "volume": 1.2,
    "tone": 0.3
  }
}
  • pitch … 音の高さの倍率。1 未満で低くなる。[最小, 最大] で書くと、換装画面の「音の低さ」でその範囲を動かせる
  • volume … 音量の倍率（0〜2）
  • tone … 「音の低さ」の最初の位置（0 でいちばん高い、1 でいちばん低い。省略で 0）
  • 下げるのは 0.78 くらいまでよく効く。上げるのはほとんど効かない（甲高くしたいなら、次の「音源ごと差し替えたい」）
Make it deeper or louder

Add a looks JSON, assets/mypack/car_parts/titanium.json (same file name as the definition):

{
  "exhaust": {
    "pitch": [0.85, 1.00],
    "volume": 1.2,
    "tone": 0.3
  }
}
  • pitch — pitch multiplier; below 1 is deeper. Written as [min, max], the parts screen's "Deepness" slider moves within it
  • volume — volume multiplier (0 to 2)
  • tone — where the "Deepness" slider starts (0 = highest, 1 = lowest; default 0)
  • Going down works well to about 0.78. Going up barely works (for a high-pitched exhaust, see "Use your own sound" below)

  1. 音源を置く（OGG・モノラル、継ぎ目なくループするもの）。assets/mypack/sounds/titanium_exhaust.ogg
  2. パックの assets/mypack/sounds.json にサウンドイベントを書く: 
    {
  "titanium_exhaust": {
    "sounds": [{ "name": "mypack:titanium_exhaust" }],
    "attenuation_distance": 64
  }
}
  3. 見た目の JSON の exhaust で指す: 
    {
  "exhaust": { "sound": "mypack:titanium_exhaust" }
}

高回転まで音程を伸ばしたいときは、1 オクターブ上の音源も作って "sound_high" で指します。sound_tools/make_octave_up.py で作れます。音源の作り方の詳しいことは車の 7 章と同じです。

Use your own sound
  1. Add the sound (OGG, mono, a seamless loop): assets/mypack/sounds/titanium_exhaust.ogg
  2. Declare a sound event in your pack's assets/mypack/sounds.json: 
    {
  "titanium_exhaust": {
    "sounds": [{ "name": "mypack:titanium_exhaust" }],
    "attenuation_distance": 64
  }
}
  3. Point to it from exhaust in the looks JSON: 
    {
  "exhaust": { "sound": "mypack:titanium_exhaust" }
}

To keep the pitch rising at high revs, also make a one-octave-up copy and point "sound_high" at it; sound_tools/make_octave_up.py makes one. More on making sounds in chapter 7 of the Car guide.

{
  "values": { ... },
  "default_parts": {
    "exhaust": { "part": "mypack:stock", "removable": false }
  }
}

Make the stock exhaust a separate object too (e.g. part_exhaust-stock), give it a part, and make it a default part at the top level of the car's spec data/mypack/cars/<car>.json. If removing it would leave just a hole, make it non-removable:

{
  "values": { ... },
  "default_parts": {
    "exhaust": { "part": "mypack:stock", "removable": false }
  }
}

More on default parts in chapter 2, "Have it fitted from the start".

うまくいかないとき
  • 「マフラー」のタブが出ない … OBJ にそのオブジェクトが入っていない。非表示のまま書き出していないか見る
  • 差し替えた音が鳴らず、いつもの音のまま … sound の名前が sounds.json に無い。ログに警告が 1 行出ている
  • pitch を 1 より大きくしても高くならない … Minecraft の音程の上限に当たっている。高い音源を sound で差し替える
When it doesn't work
  • No "Exhaust" tab — the object is not in the OBJ. Check it was not hidden when you exported
  • Your sound does not play; it is the usual one — the sound name is missing from sounds.json. A warning is in the log
  • pitch above 1 does not raise it — Minecraft's pitch ceiling. Replace the source with a higher one via sound
